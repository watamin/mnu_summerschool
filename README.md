# 목포 급식 AI 탐험실

목포시 중·고등학교의 실제 급식과 학생 취향을 비교하는 작은 연구 도구입니다. 프로그램은 완성되어 있습니다. 학생은 학교별 핵심·가치 음식을 찾고, 실제 음식 30개를 평가해 개인 추천과 음식 지도를 만든 뒤, 식사 전 예측과 식사 후 리뷰의 차이를 분석합니다.

저장소에는 2026년 6월 1일부터 7월 29일까지를 조회해 받은 목포시 중·고교 31개교의 중식 674일이 들어 있습니다. 실제 수록 식단일은 6월 24일부터 7월 29일까지입니다. 수업 담당자가 제공한 목포대학교 학생식당 7월 30·31일 메뉴도 함께 두었습니다. 목포대 메뉴는 NEIS 자료가 아니며 원문을 고치지 않고 별도 파일에 보관했습니다.

## 먼저 실행할 프로그램

처음 한 번만 가상환경과 기본 패키지를 준비합니다.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-jupyter.txt
```

NVIDIA NIM 해설 기능을 쓸 때만 저장소의 한 단계 위 폴더에 키 파일을 둡니다.

```powershell
notepad ..\nvidia_nim.txt
```

메모장 첫 줄에 발급받은 `nvapi-`로 시작하는 키만 붙여 넣고 저장합니다. 키는 저장소 안에 복사하지 않습니다. 키 파일이 없어도 TF-IDF, 역행렬 추천, 음식 지도, 리뷰 분석은 모두 실행됩니다.

완성된 서비스를 엽니다.

```powershell
.\.venv\Scripts\python.exe mokpo_service.py
```

브라우저가 자동으로 열리지 않으면 PowerShell에 표시된 `http://127.0.0.1:7860` 주소로 들어갑니다. 서버는 교사 PC 안에서만 열리고 외부 공유 링크를 만들지 않습니다.

GPU 임베딩 설치, 7월 30·31일 운영 순서, 익명 CSV 합치기는 [교사용 목포 급식 AI 서비스 운영 안내](docs/교사용_목포_급식_AI_서비스.md)에 정리했습니다. 학생은 [급식 예측·리뷰 활동지](docs/학생_급식_예측_리뷰_활동지.md)를 사용합니다.

## 서비스에서 할 수 있는 일

- 콘텐츠 기반 추천: 좋아하는 메뉴와 실제 식단 문장을 비교해 학교별 Best·Worst를 찾습니다.
- 목포대 식사 전 예측: 7월 30일과 31일의 예상 만족도를 실제 식사 전에 기록합니다.
- 유저 기반 추천: 대상 학생의 정답을 가리고, 다른 익명 학생의 리뷰와 공통 기록으로 다시 예측합니다.
- 혼합 추천: 콘텐츠 기반 점수와 유저 기반 점수를 함께 사용합니다.
- 실제 리뷰 비교: 세 추천 방식의 MAE(평균 절대 오차)를 같은 기준으로 비교합니다.
- 30개 음식 추천: 선택 학교의 실제 음식 30개를 1~5점으로 평가하고 정규화 의사역행렬로 미평가 음식의 만족도를 예측합니다.
- 음식 유사도 지도: 음식 이름의 글자 N-그램 TF-IDF 벡터를 두 축으로 줄여 가까운 음식과 먼 음식을 살펴봅니다.
- 학교 분석: 학교별 최다·최소 메뉴, 자주 나온 핵심 음식, TF-IDF 데이터 가치 음식, 급식 취향 기준 고등학교 순위를 봅니다.
- NVIDIA NIM 해설: 선택 학교의 실제 통계와 계산 결과 안에서 TF-IDF·추천 결과에 관한 질문에 한국어로 답합니다.
- 모둠 탐색: 밥친구, 식성 군집, Food MBTI, 메뉴 조합, Pareto 후보를 살펴봅니다.

이름이나 학번 대신 다음과 같은 익명 취향만 입력합니다.

- 좋아하는 재료나 메뉴
- 피하고 싶은 재료나 메뉴
- 밥·면·국물·튀김·디저트 가운데 선호하는 종류
- 매운맛 선호도 1~5
- 수업에서 시험할 가상 알레르기 주의 번호

추천 결과에는 메뉴 이름과 점수뿐 아니라 순위가 달라진 까닭도 함께 표시됩니다. 실제 만족도는 1~5점으로 입력하고 분석 화면에서는 20~100점으로 환산해 예측과 같은 눈금에서 비교합니다.

모둠 인원이 6명이라 유저 기반 추천 결과는 작은 사례 연구입니다. 학교 선택은 통학, 교육과정, 진로 등을 함께 판단해야 하며 급식 취향 순위만으로 결정하지 않습니다. 가성비·잔반·영양 편차도 실제 원가나 잔반 측정값이 아니라 공개 데이터로 만든 수업용 대체지표입니다.

## 추천 순위는 어떻게 정할까요?

메뉴 문장은 2~4글자 n-gram으로 나뉩니다. TF는 한 메뉴 안에서 각 조각이 차지하는 비율을, DF는 그 조각이 들어 있는 메뉴 수를 셉니다. IDF는 여러 메뉴에서 드문 조각에 더 큰 값을 주고, TF와 IDF를 곱한 값들을 모아 TF-IDF 벡터를 만듭니다. 03장은 작은 문서 A·B·C의 여섯 줄 계산표로 시작해 등장 횟수→전체 단어 수→TF→DF→IDF→TF-IDF를 한 칸씩 확인합니다. 이어 공개 라이선스의 한국어 문서 세 편에서 문서별 분석 단어 수와 상위 여덟 단어의 실제 계산식을 표시하고, 같은 단어가 세 문서에서 받은 점수도 비교합니다. 마지막에는 가상 취향과 급식 메뉴의 날짜별 유사도 순위, 직접 포함 단어, 공통 글자 조각 수를 연결합니다. 코사인 유사도에 좋아하는 항목, 피하고 싶은 항목, 메뉴 종류, 매운맛 차이를 더해 최종 추천 순서를 정합니다.

```text
0~100으로 제한(
  20
  + 70 × 텍스트 유사도
  + 8 × 좋아하는 항목 일치 수
  + 5 × 선호 종류 일치 수
  - 18 × 피하고 싶은 항목 일치 수
  - 3 × 매운맛 차이
)
```

이 점수는 취향을 비교하기 위한 수업용 값입니다. 건강 점수도 아니고, 실제 만족도를 예측한 값도 아닙니다. K-Means로 표시하는 식단 묶음 역시 주어진 기간 안에서 영양 수치가 비슷한 날을 모은 결과일 뿐 건강 등급이 아닙니다.

## 데이터와 안전

- 기본 학교는 남악고등학교입니다. NEIS 교육청 코드는 `Q10`, 학교 코드는 `7140272`입니다.
- 부록 A에서는 값 하나부터 목록·사전·중첩·JSON 문자열·실제 예비 파일 순서로 천천히 연습합니다.
- 01장에서는 JSON 문법을 반복하지 않고 급식식단정보 API의 주소·조건·GET·상태 코드·예비 자료 전환에 집중합니다.
- 인증키가 없는 NEIS 호출은 공식 포털의 샘플 제한에 따라 최대 5건만 받습니다. 별도 인증키는 코드나 노트북에 적지 않고 `NEIS_API_KEY` 환경 변수로만 읽습니다.
- 인터넷이나 NEIS 서버에 문제가 생기면 저장소의 예비 데이터로 같은 실습을 이어 갑니다.
- TF-IDF 문서 실습은 `AI-For-Beginners`의 MIT 라이선스 한국어 원문 세 편과 출처·SHA-256 기록을 저장소에 함께 두어 인터넷 없이도 실행됩니다.
- 이름, 학번, 반, 연락처, 체중, 질병명은 입력하거나 저장하지 않습니다.
- 실제 학생과 연결되는 알레르기 정보도 입력하지 않습니다. 알레르기 번호는 제외 규칙을 확인하는 가상 입력으로만 사용합니다.
- 실제 식단과 알레르기 정보는 학교 급식표와 영양사 안내를 다시 확인해야 합니다.
- 기본 분석에는 로그인이나 외부 AI API가 필요하지 않습니다. `NVIDIA NIM 데이터 해설` 탭만 별도 NIM API 키와 인터넷 연결을 사용합니다.
