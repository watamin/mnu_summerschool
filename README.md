# 목포 급식 AI 탐험실

목포시 학교 급식에서 뽑은 음식 30개를 평가하고, 목포대학교 학생식당의 오늘 점심을 얼마나 좋아할지 식사 전에 예상하는 실험 도구입니다. 학생은 자기 이름으로 평가를 저장한 뒤 예상 점수를 확인하고, 식사 후 실제 만족도를 입력해 두 값의 차이를 비교합니다.

저장소에는 2026년 6월 1일부터 7월 29일까지를 조회해 받은 목포시 중·고교 31개교의 중식 674일이 들어 있습니다. 실제 수록 식단일은 6월 24일부터 7월 29일까지입니다. 수업 담당자가 제공한 목포대학교 학생식당 7월 30·31일 메뉴도 함께 두었습니다. 목포대 메뉴는 NEIS 자료가 아니며 원문을 고치지 않고 별도 파일에 보관했습니다.

## 먼저 실행할 프로그램

처음 한 번만 가상환경과 기본 패키지를 준비합니다.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-jupyter.txt
```

교사 PC에서만 확인할 때는 다음처럼 엽니다.

```powershell
.\.venv\Scripts\python.exe mokpo_service.py
```

브라우저가 자동으로 열리지 않으면 PowerShell에 표시된 `http://127.0.0.1:7860` 주소로 들어갑니다. 서버는 교사 PC 안에서만 열리고 외부 공유 링크를 만들지 않습니다.

학생들이 각자 PC로 접속할 때는 LAN 모드로 엽니다. 별도의 로그인이나 비밀번호 파일은 사용하지 않습니다.

```powershell
.\.venv\Scripts\python.exe mokpo_service.py --lan
```

학생은 브라우저에서 `http://교사PC의_IPv4주소:7860`을 열고 화면의 이름 칸에 자기 이름을 입력합니다. 같은 이름으로 다시 불러오면 이전 평가가 이어집니다. 식전 예상과 식후 기록은 [급식 예측·리뷰 활동지](docs/학생_급식_예측_리뷰_활동지.md)와 함께 사용할 수 있습니다.

## 서비스에서 할 수 있는 일

- 30개 음식 평가: 이름별로 배정된 음식에 1점부터 5점까지 입력합니다.
- 프로필 저장과 이어 하기: 답한 평점은 교사 PC의 SQLite에 저장되며 같은 이름으로 다시 불러옵니다.
- 오늘 점심 예상: 저장된 30개 평점과 메뉴 이름의 n-gram TF-IDF 유사도를 이용해 메뉴별 예상 선호도와 전체 예상 점수를 계산합니다.
- 예측 근거 확인: 각 메뉴와 이름이 비슷했던 평가 음식, 평점, 유사도를 함께 보여 줍니다.
- 식후 비교: 1점부터 5점까지의 실제 만족도를 입력하면 식전 예상과의 차이와 절대 오차를 계산합니다.
- 학생·메뉴 혼용 방지: 이름이나 점심 날짜가 바뀌면 이전 예측을 비교에 사용하지 않고 다시 예상하도록 안내합니다.
- 고등학교 주요 반찬 탭: 목포 지역 고등학교 급식 전체에서 밥·국·김치·면·후식류를 제외한 주요 반찬을 TF-IDF로 보여 줍니다.

## 추천 순위는 어떻게 정할까요?

부록 B에서는 평점 데이터의 메뉴를 특성 `X`, 실제 평점을 정답 `y`로 나눕니다. `["밥", "국", "김치", "돈까스"]` 어휘표에서 김치를 `[0, 0, 1, 0]`으로 바꾸고, 음식별 평균 `[4.5, 3.5, 5.0, 4.0]`을 학습된 값으로 사용합니다. 두 벡터의 내적으로 김치 예상 평점 5.0을 계산한 뒤, 따로 둔 실제 평점 4.0과 비교해 절대오차 1.0을 확인합니다. 한 식단의 여러 음식은 `[1, 0, 1, 1]` 멀티-핫으로 나타냅니다.

메뉴 문장은 2~4글자 n-gram으로 나뉩니다. TF는 한 메뉴 안에서 각 조각이 차지하는 비율을, DF는 그 조각이 들어 있는 메뉴 수를 셉니다. IDF는 여러 메뉴에서 드문 조각에 더 큰 값을 주고, TF와 IDF를 곱한 값들을 모아 TF-IDF 벡터를 만듭니다. 03장은 작은 문서 A·B·C의 여섯 줄 계산표로 시작해 등장 횟수→전체 단어 수→TF→DF→IDF→TF-IDF를 한 칸씩 확인합니다. 이어 공개 라이선스의 한국어 문서 세 편에서 문서별 분석 단어 수와 상위 여덟 단어의 실제 계산식을 표시하고, 같은 단어가 세 문서에서 받은 점수도 비교합니다. 마지막에는 가상 취향과 급식 메뉴의 날짜별 유사도 순위, 직접 포함 단어, 공통 글자 조각 수를 연결합니다. 코사인 유사도에 좋아하는 항목, 피하고 싶은 항목, 메뉴 종류, 매운맛 차이를 더해 최종 추천 순서를 정합니다.

```text
0~100으로 제한(
  20
  + 70 × 텍스트 유사도
  + 8 × 좋아하는 항목 일치 수
  + 5 × 선호 종류 일치 수
  - 18 × 피하고 싶은 항목 일치 수
  - 3 × 매운맛 차이
)
```

이 점수는 취향을 비교하기 위한 수업용 값입니다. 건강 점수도 아니고, 실제 만족도를 예측한 값도 아닙니다. K-Means로 표시하는 식단 묶음 역시 주어진 기간 안에서 영양 수치가 비슷한 날을 모은 결과일 뿐 건강 등급이 아닙니다.

학교와 상관없는 음식 중요도는 모든 학교에서 같은 음식 이름을 한 행으로 합친 뒤 계산합니다. 전체 TF는 해당 음식의 전체 등장 횟수를 수집된 전체 음식 수로 나눈 값이고, IDF는 그 음식이 나온 학교가 적을수록 커집니다. 현재 수록본의 1위는 배추김치로, 전체 4,706개 음식 항목 중 349회 등장했고 31개교 중 27개교에서 확인되었습니다. 이 순위는 수집 자료에서의 정보량을 뜻하며 맛이나 영양 순위는 아닙니다.

## 데이터와 안전

- 기본 학교는 남악고등학교입니다. NEIS 교육청 코드는 `Q10`, 학교 코드는 `7140272`입니다.
- 부록 A에서는 값 하나부터 목록·사전·중첩·JSON 문자열·실제 예비 파일 순서로 천천히 연습합니다.
- 부록 B에서는 데이터셋→특성 X·정답 y→원-핫→학습된 값→예측→절대오차→멀티-핫 순서로 머신러닝의 기본 흐름을 연습합니다.
- 01장에서는 JSON 문법을 반복하지 않고 급식식단정보 API의 주소·조건·GET·상태 코드·예비 자료 전환에 집중합니다.
- 인증키가 없는 NEIS 호출은 공식 포털의 샘플 제한에 따라 최대 5건만 받습니다. 별도 인증키는 코드나 노트북에 적지 않고 `NEIS_API_KEY` 환경 변수로만 읽습니다.
- 인터넷이나 NEIS 서버에 문제가 생기면 저장소의 예비 데이터로 같은 실습을 이어 갑니다.
- TF-IDF 문서 실습은 `AI-For-Beginners`의 MIT 라이선스 한국어 원문 세 편과 출처·SHA-256 기록을 저장소에 함께 두어 인터넷 없이도 실행됩니다.
- 서비스는 화면에 입력한 이름과 음식별 1~5점만 교사 PC의 SQLite에 저장합니다. 학번, 반, 연락처, 체중, 질병명은 저장하지 않습니다.
- 실제 학생과 연결되는 알레르기 정보도 입력하지 않습니다. 알레르기 번호는 제외 규칙을 확인하는 가상 입력으로만 사용합니다.
- 실제 식단과 알레르기 정보는 학교 급식표와 영양사 안내를 다시 확인해야 합니다.
- 로컬 실행과 `--lan` 실행 모두 로그인 없이 열립니다. 학생은 화면의 이름 칸을 사용하며, 점심 예측에는 외부 AI API 키나 인터넷 연결이 필요하지 않습니다.
