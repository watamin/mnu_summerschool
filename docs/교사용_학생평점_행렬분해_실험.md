# 학생 평점 저장과 행렬분해 실험 운영 안내

이 실험에서는 교사 PC 한 대가 작은 서버가 된다. 학생 여섯 명은 같은 학교 네트워크에서 웹페이지에 접속해 음식 30개를 평가한다. 응답은 교사 PC의 SQLite 파일 하나에 저장되므로 학생 PC에서 파일을 따로 모을 필요가 없다.

## 1. 수업 전에 준비할 것

프로젝트 폴더는 다음 위치라고 가정한다.

```text
C:\Users\user\Documents\New project\mnu_summerschool
```

PowerShell에서 프로젝트 폴더로 이동한 뒤 가상환경이 실제로 있는지 확인한다.

```powershell
cd "C:\Users\user\Documents\New project\mnu_summerschool"
Test-Path .\.venv\Scripts\python.exe
```

`True`가 나오면 설치가 되어 있다. `False`라면 다음 명령을 한 줄씩 실행한다.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-jupyter.txt
.\.venv\Scripts\python.exe -m pip check
```

## 2. 로그인 비밀번호 파일

공통 비밀번호는 Python 코드나 GitHub 저장소에 넣지 않는다. 프로젝트 폴더의 한 단계 위에 `mokpo_password.txt`라는 텍스트 파일을 두고 첫 줄에 교사가 정한 값 하나만 적는다.

```powershell
notepad ..\mokpo_password.txt
```

현재 교사 PC에는 요청한 값으로 파일이 준비되어 있다. GitHub에 올릴 때 이 파일이 포함되지 않는지 항상 확인한다. 한 개의 공통 비밀번호를 쓰므로 학생이 다른 학생 이름을 입력하는 행위까지 시스템이 구별하지는 못한다. 수업 시작 때 좌석과 로그인 이름을 한 번 확인한다.

## 3. 학생 접속용으로 실행하기

```powershell
.\.venv\Scripts\python.exe mokpo_service.py --lan
```

프로그램은 `0.0.0.0`에서 요청을 받지만 공개 인터넷 링크를 만들지는 않는다. 학생에게 알려 줄 주소는 `0.0.0.0`이 아니라 교사 PC의 IPv4 주소다.

```powershell
ipconfig
```

학교 네트워크 어댑터 아래의 `IPv4 주소`가 예를 들어 `192.168.0.25`라면 학생이 열 주소는 다음과 같다.

```text
http://192.168.0.25:7860
```

Windows 방화벽 창이 처음 뜨면 학교 네트워크가 사설 네트워크로 설정되어 있는지 확인한 뒤 Python의 사설 네트워크 접근만 허용한다. 공용 네트워크 허용은 선택하지 않는다.

## 4. 학생이 평가하는 순서

1. 브라우저에서 교사가 알려 준 주소를 연다.
2. 사용자 이름에는 자기 이름을, 비밀번호에는 교사가 알려 준 공통값을 입력한다.
3. `내 프로필·30개 평가` 탭을 연다.
4. `내 평가표 불러오기`를 누른다. 로그인한 이름이 화면에 나타나는지 확인한다.
5. 음식마다 1점(매우 싫음)부터 5점(매우 좋음)까지 매긴다. 0은 아직 답하지 않은 칸이다.
6. 중간에 한 번 `평점 저장`을 누른다. 화면의 저장 수가 예를 들어 `12/30`처럼 바뀌는지 확인한다.
7. 30개를 모두 답하고 다시 저장한다. `30/30`과 완료 안내가 나오면 끝이다.

새로 고침하거나 브라우저를 닫아도 저장값은 교사 PC에 남는다. 같은 이름으로 로그인하면 같은 30개 음식과 기존 평점이 복원된다. 음식 이름·구분·행 순서를 고치면 저장이 거절되므로 평점 열만 바꾼다.

## 5. 왜 학생마다 30개가 조금 다른가

전체 실험 음식은 실제 NEIS 수집 급식에서 TF-IDF 데이터 가치가 높았던 45개다.

- 모두가 같은 공통 음식: 15개
- 학생마다 돌아가며 받는 순환 음식: 15개
- 그 학생이 평가하지 않은 진짜 빈칸: 15개

여섯 명이 차례로 프로필을 만들면 각 순환 음식도 세 명씩 평가한다. 따라서 다른 학생과 겹치는 평점이 생기면서 각 학생에게는 예측할 빈칸이 남는다. 질문 배정은 처음 만들 때 DB에 저장되므로 다시 접속해도 바뀌지 않는다.

## 6. 행렬분해 결과 계산하기

학생 평가가 모이면 교사가 `학생 행렬분해 실험` 탭에서 `현재 저장값으로 행렬분해`를 누른다.

```text
예측평점(u, i) = 전체평균 + 학생편향(u) + 음식편향(i) + P[u] · Q[i]
```

- `전체평균`: 모인 모든 실제 평점의 평균이다.
- `학생편향`: 평소 점수를 높게 또는 낮게 주는 학생의 경향이다.
- `음식편향`: 여러 학생에게 대체로 높거나 낮은 점수를 받은 음식의 경향이다.
- `P[u] · Q[i]`: 학생과 음식의 보이지 않는 취향 특징 세 개를 곱해 더한 값이다.

`실제 평점 행렬`은 학생이 입력한 칸만 보여 준다. `빈칸 완성 행렬`은 실제 셀에 `실제`, 채운 셀에 `예측`이라고 표시한다. 열지도에서는 검은 점이 실제, 흰 테두리가 예측이다.

## 7. MAE는 어느 칸으로 계산하는가

진짜 빈칸은 학생이 평가하지 않았으므로 정답을 모른다. 이 빈칸으로 정확도를 계산하면 안 된다. 프로그램은 이미 알고 있는 실제 평점 일부를 잠시 가리고 학습한 뒤, 가린 값을 얼마나 가깝게 맞혔는지 확인한다.

- 행렬분해 MAE: `|실제값 - 예측값|`의 평균
- 행렬분해 RMSE: 큰 오차에 더 큰 벌점을 주는 지표
- 전체평균 기준선 MAE: 모든 학생과 음식에 같은 평균을 준 단순 방법의 오차

행렬분해 MAE가 기준선 MAE보다 작으면 학생과 음식의 패턴을 사용한 것이 단순 평균보다 도움이 된 사례다. 더 크면 이 작은 모둠에서는 행렬분해가 오히려 도움이 되지 않았다는 결과이며, 실패를 숨기지 않고 그대로 분석한다.

## 8. 저장 파일과 백업

기본 DB 파일은 다음 위치에 생긴다.

```text
runtime_data\student_profiles.sqlite3
```

이 폴더는 Git에 올라가지 않는다. 수업 뒤 `전체 실제 평점 CSV` 버튼으로 긴 형식 CSV를 내려받는다. DB 자체를 백업하려면 서비스를 `Ctrl+C`로 먼저 종료한 뒤 `runtime_data` 폴더를 다른 이름으로 복사한다.

새 실험을 시작할 때는 기존 파일을 바로 지우기보다 서비스를 종료하고 다음처럼 날짜가 붙은 이름으로 옮긴다.

```powershell
Move-Item .\runtime_data\student_profiles.sqlite3 .\runtime_data\student_profiles_2026-07-30.sqlite3
```

다음 실행 때 새 DB가 자동으로 만들어진다.

## 9. 수업 직전 빠른 점검

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_student_profiles.py tests\test_matrix_factorization.py tests\test_student_profile_ui.py tests\test_mokpo_service.py -q
.\.venv\Scripts\python.exe -m pip check
```

그다음 LAN 모드로 실행해 교사 PC가 아닌 다른 PC 한 대에서 로그인, 평가 두 개 저장, 새로 고침 뒤 복원까지 확인한다.

## 10. 접속이 안 될 때

- `이 사이트에 연결할 수 없음`: 학생과 교사 PC가 같은 네트워크인지, 주소가 교사 PC의 현재 IPv4인지 확인한다.
- 교사 PC에서는 되지만 학생 PC에서는 안 됨: Windows 방화벽의 Python 사설 네트워크 허용을 확인한다.
- 비밀번호 파일 오류: `mokpo_password.txt`가 프로젝트 폴더 안이 아니라 한 단계 위에 있고, 비어 있지 않은 한 줄인지 확인한다.
- `.venv\Scripts\python.exe`를 찾지 못함: PowerShell의 현재 폴더가 `mnu_summerschool`인지 `Get-Location`으로 확인한다.
- 포트 충돌: `--port 7861`을 붙여 실행하고 학생 주소의 끝도 `:7861`로 바꾼다.
- 저장한 이름이 다르게 보임: 로그인 화면에서 다른 이름을 입력한 것이다. 브라우저에서 로그아웃한 뒤 정확한 이름으로 다시 들어간다.
