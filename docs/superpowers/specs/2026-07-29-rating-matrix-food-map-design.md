## 2. 용어와 점수의 의미

“가장 가치 있는 음식”은 건강, 가격, 영양 또는 학생 개인의 선호를 뜻하지 않는다.
이 서비스에서는 **수집한 학교 급식 데이터에서 한 학교를 잘 대표하는 음식**을
뜻하며, 이를 `TF-IDF 데이터 가치 점수`라고 표시한다.

학교 `s`와 음식 `t`에 대해 다음 값을 계산한다.

- `c(s,t)`: 선택 학교에서 음식이 등장한 횟수
- `T(s)`: 선택 학교의 전체 음식 항목 수
- `df(t)`: 해당 음식이 한 번 이상 등장한 학교 수
- `N`: 급식 데이터가 있는 전체 학교 수
- `TF(s,t) = c(s,t) / T(s)`
- `IDF(t) = ln((1 + N) / (1 + df(t))) + 1`
- `TF-IDF(s,t) = TF(s,t) × IDF(t)`

`TF`가 크면 그 학교에서 자주 나온 음식이고, `IDF`가 크면 다른 학교에서는
상대적으로 보기 드문 음식이다. 둘을 곱한 값이 크면 “자주 나오면서도 그 학교를
구별해 주는 음식”이다.

화면은 다음 세 결과를 구분해 보여 준다.

1. `가장 자주 나온 핵심 메뉴`: 선택 학교에서 등장 횟수가 가장 많은 음식
2. `TF-IDF 1위 시그니처 메뉴`: 선택 학교의 TF-IDF 데이터 가치 점수가 가장 높은 음식
3. `전체 학교 TF-IDF 순위`: 학교와 음식의 모든 조합 중 점수가 높은 항목

따라서 배추김치처럼 여러 학교에서 자주 나오는 음식은 핵심 메뉴가 될 수 있지만
IDF가 작아 시그니처 순위는 낮아질 수 있다. 반대로 한 학교에 한 번만 나온 매우
희귀한 음식은 IDF가 커도 TF가 작아 반드시 1위가 되지는 않는다.

## 3. TF-IDF 계산 설명 화면

`학교별 가치 음식` 영역은 선택 학교의 상위 15개 음식을 다음 열로 표시한다.

| 열 | 의미 |
|---|---|
| 순위 | TF-IDF 내림차순 순위 |
| 음식 | 알레르기 번호와 괄호 설명을 정리한 음식명 |
| 등장 횟수 | `c(s,t)` |
| 학교 전체 음식 수 | `T(s)` |
| TF | `c(s,t) / T(s)` |
| 등장 학교 수 | `df(t)` |
| 전체 학교 수 | `N` |
| IDF | `ln((1+N)/(1+df))+1` |
| 데이터 가치 점수 | `TF × IDF` |

표 위에는 현재 1위 음식의 실제 값을 대입한 계산 문장을 자동 생성한다.

```text
돈까스의 TF = 5 ÷ 174 = 0.0287
돈까스의 IDF = ln((1 + 35) ÷ (1 + 12)) + 1 = 2.0188
TF-IDF 데이터 가치 점수 = 0.0287 × 2.0188 = 0.0579
```

숫자는 실제 선택 학교 데이터에서 계산하며 예시 숫자를 고정하지 않는다. 소수점은
TF·IDF·TF-IDF 모두 네 자리까지 표시한다. 동점은 등장 횟수 내림차순, 음식명
가나다순으로 정한다.

`전체 학교 TF-IDF 순위`는 학교, 학교급, 음식, 등장 횟수, TF, IDF, 데이터 가치
점수를 표시한다. 동일 학교·음식은 한 행만 존재한다.

## 4. 무작위 음식 30개 설문

학생은 먼저 학교를 선택하고 `음식 30개 뽑기`를 누른다. 모집단은 그 학교의 실제
급식에 등장한 중복 제거 음식명이다.

- 고유 음식이 30개 이상이면 30개를 중복 없이 뽑는다.
- 고유 음식이 30개 미만이면 모든 음식을 보여 주고 실제 개수를 안내한다.
- `다른 음식 다시 뽑기`를 누르면 직전 목록과 다른 seed를 사용한다.
- 같은 seed와 같은 데이터에서는 같은 순서를 재현한다.
- 각 음식은 1점 `매우 싫음`부터 5점 `매우 좋음`까지 평가한다.
- 초기값은 3점이며 학생은 달라지는 항목만 수정할 수 있다.
- 음식명과 평점의 두 열로 된 편집 표를 사용한다.
- 빈 값, 1~5 범위 밖 숫자, 중복 음식, 목록 변조는 분석 전에 거절한다.

30개 설문은 선택한 학교의 식단에 실제 등장한 음식만 묻는다. 별도의 자유 입력
음식은 역행렬 학습 데이터에 포함하지 않는다.

## 5. 정규화 의사역행렬 추천

설문 음식과 예측 대상 음식은 같은 문자 2~4글자 n-gram TF-IDF 공간에서 벡터화한다.
각 행은 길이가 1이 되도록 정규화한다.

- `X`: 학생이 평가한 음식의 TF-IDF 행렬, 크기 `r × d`
- `y`: 학생의 1~5점 평점 벡터, 크기 `r`
- `z = y - 3`: 보통 3점을 중심으로 이동한 평점
- `λ = 0.1`: 역행렬 계산을 안정화하는 정규화 값
- `I`: `r × r` 단위행렬

학생 취향 가중치 `w`는 다음 식으로 계산한다.

```text
G = X Xᵀ + λI
w = Xᵀ pinv(G) z
```

`pinv`는 Moore-Penrose 의사역행렬이다. `XXᵀ`가 완전한 역행렬을 갖지 않더라도
계산할 수 있고, `λI`는 서로 매우 비슷한 음식 때문에 값이 불안정해지는 것을 줄인다.

전체 음식 벡터를 `X_all`이라 하면 예상 평점은 다음과 같다.

```text
예상 평점 = clip(3 + X_all w, 1, 5)
```

결과에는 아직 평가하지 않은 메뉴만 남기고 예상 평점 내림차순으로 정렬한다.
상위 10개 추천과 하위 10개 비추천을 보여 준다. 각 결과에는 가장 큰 영향을 준
평가 음식, 그 음식에 준 점수, 코사인 유사도, 예상 평점을 함께 표시한다.

모든 평점이 3점이면 모든 예측도 3점이 되어야 한다. 높은 평점을 준 음식과 TF-IDF
벡터가 가까운 음식은 예상 평점이 올라가고, 낮은 평점을 준 음식과 가까운 음식은
내려가야 한다.

## 6. 음식 유사도 2차원 지도

2차원 지도는 다음 음식을 최대 50개까지 포함한다.

- 설문에서 평가한 음식
- 역행렬 예상 평점 상위 음식
- 선택 학교의 등장 횟수 상위 음식

TF-IDF 행렬의 열 평균을 뺀 뒤 특이값 분해(SVD)의 첫 두 축으로 좌표를 만든다.
이는 PCA와 같은 방식이며 입력이 같으면 좌표도 같다. 한 축만 만들어지는 작은
데이터는 두 번째 좌표를 0으로 채운다.

- 가까운 점: TF-IDF 글자 조각 구성이 비교적 비슷한 음식
- 점 색: 1~5점 실제 평점 또는 예상 평점
- 점 크기: 학교 식단 등장 횟수
- 테두리가 있는 점: 학생이 직접 평가한 음식
- 별표: 예상 평점 상위 5개 음식

축의 절대값 자체에는 의미가 없고 점 사이의 상대적 위치만 해석한다는 설명을
그래프 바로 아래에 둔다. 그래프와 함께 음식, X좌표, Y좌표, 실제/예상 구분,
평점, 등장 횟수 표도 제공한다.

## 9. 오류 처리

- 선택 학교에 급식 데이터가 없으면 명확한 한국어 오류를 보여 준다.
- 설문 메뉴가 2개 미만이면 행렬 추천을 실행하지 않는다.
- 평점 표가 원본 샘플과 다르면 어떤 행을 고쳐야 하는지 안내한다.
- TF-IDF 어휘가 만들어지지 않으면 추천과 지도를 빈 표로 숨기지 않고 원인을 보여 준다.
- SVD 결과에 NaN 또는 무한대가 생기면 그래프를 만들지 않고 한국어 오류를 반환한다.
- GPU 모델 설치 여부와 관계없이 새 역행렬 추천과 가치 음식 계산은 TF-IDF로 작동한다.

## 10. 검증 기준

- 기존 전체 테스트가 계속 통과한다.
- 고정 예제의 TF, IDF, TF-IDF가 손 계산 값과 일치한다.
- 선택 학교의 TF-IDF 1위가 상세 표·요약·전체 순위에서 같은 값이다.
- 같은 seed의 30개 목록은 같고 다른 seed는 데이터가 충분할 때 달라진다.
- 설문 목록은 선택 학교 실제 음식의 부분집합이며 중복되지 않는다.
- 모든 평점이 3점이면 모든 예상 평점이 3점이다.
- 선호 음식과 동일한 벡터의 미평가 음식은 반대 취향 음식보다 높은 점수를 받는다.
- 2차원 좌표는 유한한 숫자이며 입력 순서가 같으면 재현된다.
- Gradio 앱에 새 탭, 계산식, 가치 음식 표, 지도 출력이 존재한다.
- 제거 대상으로 지정한 개인정보 안내 문장이 앱 구성에 존재하지 않는다.
- 실제 서버를 실행해 첫 화면 HTTP 200과 새 콜백 실행을 확인한다.

## 11. 채택하지 않은 방식

일반 역행렬 `G⁻¹`만 사용하는 방식은 비슷한 음식이 많을 때 행렬이 특이행렬이 되어
실패할 수 있어 사용하지 않는다. 학생 6명의 평점만으로 협업 필터링 행렬 분해를
새 기본 추천으로 삼는 방식도 데이터가 모이기 전에는 작동하지 않아 제외한다.
기존 유저 기반 추천은 목포대 실제 리뷰 비교 기능에 그대로 유지한다.

## 12. NVIDIA NIM 급식 데이터 해설 챗봇

사용자가 NVIDIA NIM 사용을 위임했으므로 자유 대화형 챗봇 대신 **계산 결과를
근거로 답하는 급식 데이터 해설 도우미**를 추가한다. 자유 대화형은 수집 데이터와
관계없는 답을 만들기 쉽고, 로컬 GPU LLM은 수업 전 설치 용량과 준비 시간이 크기
때문에 채택하지 않는다.

NVIDIA 공식 호스팅 API의 OpenAI 호환
`https://integrate.api.nvidia.com/v1/chat/completions` 엔드포인트와
`meta/llama-3.1-8b-instruct` 모델을 기본값으로 사용한다. 별도의 OpenAI SDK를
추가하지 않고 기존 `requests` 패키지로 JSON 요청을 보낸다.

API 키는 다음 순서로 찾는다.

1. `NVIDIA_API_KEY` 환경변수
2. `NVIDIA_NIM_KEY_FILE` 환경변수가 가리키는 파일
3. 프로젝트 상위 폴더의 `nvidia_nim.txt`

키 파일은 키 문자열만 있는 형식과 `NVIDIA_API_KEY=nvapi-...` 형식을 모두 읽는다.
키는 브라우저로 전달하거나 Git 저장소에 복사하지 않고, 로그·오류 메시지에도
일부 문자열을 포함하지 않는다. 파일은 챗봇 요청 시 서버에서 지연 로딩한다.

챗봇 탭에서 학생은 학교를 선택한 뒤 질문한다. 요청에 포함하는 근거는 다음으로
제한한다.

- 데이터 수집 기간과 실제 식단 행 수
- 선택 학교의 급식 일수와 전체 음식 항목 수
- 가장 자주 나온 핵심 메뉴 10개와 등장 횟수
- TF-IDF 데이터 가치 상위 10개와 TF·DF·IDF·TF-IDF
- 현재 1위 메뉴의 실제 숫자 대입 계산식
- 같은 학교에서 계산한 역행렬 추천 결과가 있으면 Best·Worst 각 5개
- 최근 대화 여섯 차례

시스템 지시는 한국어 중학생 수준으로 짧게 설명하고, 제공된 근거에 없는 사실은
추측하지 말며, 영양·알레르기·건강 안전을 판정하지 말도록 정한다. 질문은 앞뒤
공백을 제외해 1~500자로 제한하고, 응답은 최대 700토큰으로 요청한다. API 호출
제한, 인증 실패, 시간 초과, 잘못된 응답은 키나 원문 응답을 노출하지 않는 한국어
메시지로 바꾼다.

화면에는 `NVIDIA NIM 데이터 해설` 탭을 추가한다. 학교 선택, 질문 예시 버튼,
대화창, 질문 입력, 보내기, 대화 지우기를 제공한다. 질문과 계산 근거가 NVIDIA
호스팅 API로 전송된다는 짧은 연결 안내만 표시한다. 기존에 제거하기로 한 긴
개인정보 경고 문단은 다시 추가하지 않는다.

`src/neis_meal_ai/nim_chat.py`는 키 파싱, 근거 프롬프트 구성, HTTP 요청과 응답
검증만 담당한다. `mokpo_ui.py`의 순수 콜백은 선택 학교의 계산 표를 만들고
`nim_chat.py`에 전달한다. 테스트는 실제 키나 네트워크를 사용하지 않고 기록형
가짜 HTTP 세션으로 URL, 헤더 비노출, 요청 JSON, 응답 파싱과 오류 변환을 검증한다.
최종 수동 검증에서만 사용자가 둔 키 파일로 한 번 호출해 한국어 응답을 확인한다.

## 13. Windows 원문 해시 호환

현재 TF-IDF 공개 문서의 기록된 SHA-256은 LF 줄바꿈 기준이다. Windows Git의
`core.autocrlf=true`가 작업 파일을 CRLF로 바꾸면 내용은 같아도 바이트 해시가
달라진다. 원문을 UTF-8로 읽은 뒤 `CRLF`와 단독 `CR`을 `LF`로 정규화한 UTF-8
바이트를 해시한다. 정규화된 해시는 기존 `sources.json` 값과 일치해야 하며 실제
분석 텍스트도 같은 LF 문자열을 사용한다. 이 변경으로 Windows와 Linux에서 같은
문서 지문과 TF-IDF 결과를 얻는다.
