# 목포권 학생 급식 AI 웹 서비스 설계

## 1. 목표와 범위

목포시 소재 중학교·고등학교의 NEIS 공개 급식 데이터를 이용해 학생이 취향 설문과 실제 만족도 피드백을 입력하고, 모둠별 결과와 학교별 식단 특징을 분석하는 완성형 로컬 Gradio 웹 서비스를 만든다. 학생은 코드를 작성하지 않고 설문 설계, 결과 비교, 예측과 실제 응답의 차이 해석에 집중한다. TF-IDF 결과와 임베딩 결과를 함께 보여 주며, 실제 평가가 입력되기 전 모델 점수는 `수업용 예측 점수`라고 표시한다.

서비스 이름은 `목포 급식 AI 탐험실`로 한다. 기존 남악고 추천기는 그대로 보존하고, 새 서비스는 `mokpo_service.py`로 실행한다. 2026년 7월 30일·31일 목포대학교 학생식당 점심은 NEIS와 구분한 별도 검증 식단으로 넣어 콘텐츠 기반·유저 기반 예측과 실제 리뷰를 비교한다.

## 2. 채택한 구현 방식

### 채택: 기존 Python·Gradio 확장

현재 저장소의 NEIS 수집, Pandas 정리, TF-IDF 추천, Gradio 화면을 재사용한다. 별도 JavaScript 프런트엔드나 데이터베이스를 추가하지 않는다. 학생은 Python 함수와 표를 연결해 전체 흐름을 이해할 수 있다.

### 제외한 방식

- Streamlit 전면 재작성: 기존 UI와 테스트를 다시 만드는 비용이 크다.
- FastAPI와 별도 프런트엔드: 배포 확장성은 높지만 15시간 수업 범위를 넘는다.
- 생성형 LLM 식단 평가: 급식 데이터만으로 근거를 검증하기 어렵고 API 비용·안전 문제가 생긴다.

## 3. 개인정보 원칙

- 실제 이름, 학번, 반, 연락처, 질병명은 받거나 저장하지 않는다.
- 화면에서 사용할 별명은 선택 사항이며 현재 요청의 결과 문구에만 쓰고 파일에 기록하지 않는다.
- 나이 대신 `중1·중2·중3·고1·고2·고3` 학년 구간을 사용한다.
- 알레르기 번호는 수업용 가상 값만 입력하게 하고 실제 건강 판단에 사용하지 않는다.
- 밥친구 기능은 `학생A`처럼 익명 표시명과 취향 문장만 한 번에 입력하며 서버·파일에 저장하지 않는다.
- 모둠 설문은 익명 참여자 코드로 구분하고, 사용자가 내려받기를 선택할 때만 CSV 파일을 만든다.

## 4. 데이터 파이프라인

### 4.1 학교 목록

NEIS `schoolInfo`에서 전남교육청 코드 `Q10`의 학교를 조회한 뒤 도로명 주소에 `목포시`가 들어 있고 학교 종류가 `중학교` 또는 `고등학교`인 행만 남긴다. 현재 조회 결과는 31개교다.

공개 저장 파일 `data/mokpo_schools.json`에는 학교명, 학교 종류, 교육청 코드, 학교 코드, 도로명 주소만 넣는다.

### 4.2 급식 데이터

31개교에 대해 2026-06-01부터 2026-07-29까지 NEIS 중식 데이터를 수집한다. `data/mokpo_meals_live.json`에는 학교 식별 정보와 날짜·메뉴·열량·영양·알레르기 등 공개 급식 필드만 넣는다. 인증키와 요청 URL은 저장하지 않는다.

수집기는 다음을 검증한다.

- 교육청 코드가 `Q10`인지 확인
- 학교 코드가 수집한 학교 목록에 있는지 확인
- 식사 종류가 `중식`인지 확인
- 날짜가 8자리 실제 날짜인지 확인
- 학교별 행 수와 전체 행 수가 메타데이터와 일치하는지 확인
- 실패 시 인증키나 전체 요청 URL이 출력되지 않도록 짧은 안내만 표시

### 4.3 학생 피드백 데이터

학생 설문은 다음 열을 가진다.

- 익명 참여자 코드: `학생A`~`학생F`처럼 수업에서 정한 값
- 학년 구간, 선택 학교, 좋아하는 메뉴, 피하고 싶은 메뉴, 매운맛 선호
- 서비스가 계산한 예측 만족도 0~100
- 학생이 급식을 먹고 입력한 실제 만족도 1~5
- 선택형 피드백 태그: `맛`, `양`, `매운맛`, `메뉴 조합`, `기타`
- 식단 ID와 날짜, 데이터 출처(`NEIS 학교 급식` 또는 `목포대 학생식당 검증 식단`)
- 콘텐츠 기반 예측, 유저 기반 예측, 두 값을 합친 혼합 예측

응답은 현재 브라우저 세션의 `gr.State`에만 모은다. 학생은 최대 6명의 응답을 표로 확인하고 CSV로 내려받을 수 있다. 다시 분석할 때는 같은 CSV를 업로드하며, 실제 이름이나 자유 서술형 개인정보는 받지 않는다.

### 4.4 목포대학교 학생식당 검증 식단

사용자가 제공한 다음 두 점심 식단을 `data/mnu_cafeteria_2026_07_30_31.json`에 원문 그대로 보존한다.

- 2026-07-30: 부대찌개, 잡곡밥, 등심돈까스, 고구마대나물, 비엔나떡볶음, 배추김치
- 2026-07-31: 계란파국, 보조밥, 투움바스파게티, 오이피클/페투치제면, 양상추템더샐러드, 배추김치/요구르트

이 파일은 NEIS 수집본이 아니며 출처를 `수업 담당자 제공 목포대 학생식당 식단`으로 표시한다. 메뉴 표기는 제공된 원문을 임의로 교정하지 않는다.

## 5. AI와 분석 기능

### 5.1 개인 Best·Worst와 만족도 예측

입력은 익명 참여자 코드, 학년 구간, 좋아하는 음식, 피하고 싶은 음식, 선호 유형, 매운맛 단계다. 메뉴 문장과 취향 문장의 코사인 유사도를 0~1로 계산하고 다음 공개 규칙으로 0~100점 만족도를 만든다.

- 텍스트 유사도 70점
- 선호 유형 일치 최대 15점
- 매운맛 차이 최대 10점 감점
- 피하고 싶은 키워드 한 개당 20점 감점
- 점수는 0~100으로 제한

가장 높은 메뉴 5개와 가장 낮은 메뉴 5개를 함께 보여 준다. 실제 설문 정답이 없는 상태이므로 이 값은 예측 모델의 결과이지 학생의 실제 만족도가 아니다.

### 5.2 유저 기반 추천과 혼합 추천

콘텐츠 기반 점수는 학생 취향 문장과 메뉴 문장의 유사도로 계산한다. 유저 기반 점수는 다른 익명 학생들의 실제 1~5점 리뷰를 사용한다.

특정 학생·식단의 유저 기반 예측에서는 그 식단의 실제 점수를 가리고 다음 순서로 계산한다.

1. 대상 학생과 다른 학생이 함께 평가한 다른 식단을 찾는다.
2. 공통 식단 평점 차이의 평균으로 `1 - 평균 절대 차이 / 4` 유사도를 만든다.
3. 대상 식단을 평가한 다른 학생들의 평점을 유사도로 가중 평균한다.
4. 공통 평가가 없으면 대상 식단의 모둠 평균, 그것도 없으면 전체 평균을 사용한다.
5. 1~5점 예측을 20~100으로 바꿔 콘텐츠 점수와 같은 축에서 비교한다.

혼합 예측은 유저 기반에 공통 평가가 있으면 콘텐츠 50%와 유저 기반 50%, 없으면 콘텐츠 80%와 유저 기반 20%로 계산한다. 리뷰가 모두 모인 뒤에는 각 실제 점수를 한 번씩 가리고 다시 예측하는 leave-one-item-out 방식으로 두 7월 식단의 예측 오차를 비교한다.

### 5.3 TF-IDF와 임베딩

기본 모드는 기존 문자 n-gram TF-IDF다. 선택 모드에서는 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`를 지연 로딩한다. 모델은 50개 언어를 지원하고 384차원 밀집 벡터를 만들며, 메뉴와 취향 벡터를 정규화한 뒤 내적으로 코사인 유사도를 구한다.

PyTorch가 CUDA를 사용할 수 있으면 GPU를 선택하고 그렇지 않으면 CPU를 사용한다. 모델 패키지나 가중치가 없으면 서비스가 멈추지 않고 TF-IDF로 전환하며 화면에 전환 이유를 표시한다. 자동 테스트에서는 실제 모델을 다운로드하지 않고 고정된 가짜 임베더로 계산 경계를 검증한다.

### 5.4 학교 통계와 시그니처 메뉴

- 학교별 급식 일수, 메뉴 항목 수, 평균 열량
- 학교별 자주 등장한 메뉴와 적게 등장한 메뉴
- 전체 학교에는 흔하지 않지만 특정 학교에서 상대적으로 자주 등장한 단어를 TF-IDF로 계산한 시그니처 키워드
- 학생 취향과 각 학교 식단의 평균 상위 유사도를 비교한 `입맛 맞춤형 학교 추천`

학교 추천은 교육의 질이나 진학 적합도를 평가하지 않으며 급식 취향만 비교한다고 명시한다.

### 5.5 Food MBTI와 밥친구

Food MBTI는 네 가지 설명 축을 사용한다.

- `R/E`: 밥·국 중심 / 면·간편식 중심
- `M/S`: 순한 맛 / 매운 맛
- `F/L`: 익숙한 메뉴 / 새로운 메뉴
- `D/H`: 디저트 선호 / 든든한 식사 선호

질문 응답과 메뉴 키워드로 네 글자 유형을 결정하고 근거를 출력한다. 이는 성격검사가 아니라 수업용 식성 분류다.

밥친구는 최대 6명의 익명 취향 문장을 벡터화한 뒤 모든 학생 쌍의 코사인 유사도를 계산하고 가장 가까운 짝을 추천한다. 동점은 입력 순서로 결정한다.

### 5.6 모둠 피드백 분석

세션에 모은 응답 또는 업로드한 CSV로 다음을 계산한다.

- 참여자별 예측 점수와 실제 만족도 환산 점수(`1~5점 × 20`)의 차이
- 평균 실제 만족도, 예측 평균, 평균 절대 오차
- 7월 30·31일 목포대 식단의 콘텐츠·유저 기반·혼합 예측 MAE 비교
- Best·Worst 실제 평가 메뉴
- 학년 구간과 피드백 태그별 응답 수
- 학생 간 취향 유사도와 밥친구
- 취향 벡터를 결정적 K-Means로 묶은 모둠 식성 군집

응답이 2개 미만이면 군집이나 밥친구를 만들지 않고 더 많은 응답이 필요하다고 안내한다. 6명 이하의 작은 표본이므로 통계적 일반화는 하지 않는다.

### 5.7 식단 실험실과 메뉴 조합

NEIS에는 식재료 원가와 잔반 실측값이 없다. 따라서 이 기능은 다음 대체지표를 사용하는 `수업용 가정 시뮬레이션`으로 표시한다.

- 가성비 대체지표: 메뉴 항목 수 대비 취향 점수
- 잔반 위험 대체지표: `100 - 익명 집단 평균 만족도 예측`
- 영양 균형 대체지표: 선택 학교 평균 열량에서 벗어난 정도

가성비는 높고 잔반 위험은 낮은 비지배 메뉴를 Pareto 후보로 표시한다. 꿀조합·꽝조합은 같은 날 함께 나온 메뉴 쌍의 빈도와 학생 취향 유사도를 이용한 탐색용 추정치이며 실제 섭취량이나 선호도 조사 결과가 아님을 표시한다.

## 6. 화면 구성

### 공통 상단

- 데이터 범위, 학교 수, 급식 일수
- TF-IDF와 임베딩의 차이
- 개인정보·알레르기·예측 한계 안내

### 탭 1: 학생 설문·개인 결과

학교 또는 목포대 7월 30·31일 검증 식단, 익명 참여자 코드, 학년 구간, 취향, 분석 방식을 선택한다. Best·Worst 표, 만족도 막대그래프, 계산 근거를 출력한다. 실제 급식을 먹은 뒤 만족도와 피드백 태그를 선택해 현재 모둠 응답에 추가한다.

### 탭 2: 모둠 피드백 분석

현재 세션 응답 또는 업로드한 CSV를 분석해 콘텐츠·유저 기반·혼합 예측과 실제 평가 차이, Best·Worst 실제 메뉴, Food MBTI, 밥친구, 군집을 보여 준다. 특히 목포대 7월 30·31일 식단은 날짜별 오차표로 제공한다. 현재 응답을 CSV로 내려받는 버튼도 둔다.

### 탭 3: 학교 급식 지도

학교 종류와 학교를 선택해 빈도 통계와 시그니처 키워드를 보고, 취향 문장을 입력해 급식 취향 기준 고등학교 추천을 확인한다.

### 탭 4: AI 식단 실험실

학교와 익명 집단 취향을 선택해 Pareto 후보와 메뉴 조합 추정치를 본다. 실제 원가·잔반 데이터가 아니라는 경고를 결과 바로 위에 둔다.

## 7. 오류 처리

- 다중 학교 JSON이 없거나 손상되면 시작 화면에서 교사용 수집 명령을 안내한다.
- 일부 학교에 급식이 없으면 해당 학교만 제외하고 제외 학교 수를 표시한다.
- 임베딩을 사용할 수 없으면 TF-IDF로 전환한다.
- 입력이 비어 있거나 형식이 잘못되면 학생이 고칠 항목을 한국어로 알려 준다.
- UI 콜백은 인증키 파일을 읽지 않으며 네트워크 요청도 하지 않는다.

## 8. 검증 기준

- 저장소에 인증키가 포함되지 않는다.
- 목포시 중·고교 목록이 31개이며 중학교와 고등학교가 모두 포함된다.
- 공개 급식 스냅샷의 모든 행이 허용 학교·중식·유효 날짜다.
- TF-IDF와 가짜 임베딩 모드에서 코사인 유사도 결과가 재현된다.
- Best와 Worst가 겹치지 않고 점수는 0~100이다.
- 설문 CSV의 열·점수 범위를 검증하고 실제 평가와 예측 차이가 정확히 계산된다.
- 목포대 두 식단이 제공 원문과 날짜를 유지하고 NEIS가 아닌 별도 출처로 표시된다.
- 유저 기반 예측이 대상 평점을 사용하지 않으며 공통 리뷰 유무에 따라 가중치와 fallback이 결정된다.
- 콘텐츠·유저 기반·혼합 추천의 MAE가 손으로 계산한 고정 예제와 일치한다.
- 2~6명의 익명 응답에서 학교 시그니처, 밥친구, Food MBTI, 군집, Pareto 후보가 결정적으로 계산된다.
- Gradio 앱이 네 탭과 설문 저장 범위·개인정보·작은 표본·모델 한계 안내를 포함한다.
- GPU 환경에서는 실제 임베딩 모델이 CUDA 장치에서 한 번 이상 문장을 벡터화한다.
- 기존 Jupyter 교과서와 남악고 추천기 테스트가 계속 통과한다.
