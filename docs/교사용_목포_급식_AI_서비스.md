# 목포 급식 AI 탐험실 운영 안내

이 프로그램은 교사가 미리 실행해 두고 학생 여섯 명이 실제 급식 데이터를 탐색하는 데 쓴다. 학생은 자기 이름으로 로그인해 음식 30개를 평가·저장하고, 모인 학생×음식 행렬의 빈칸을 예측한다. 이어 학교별 가치 음식과 개인 추천을 살펴보고 식사 전 예측과 식사 후 리뷰를 비교한다.

## 1. 처음 한 번 설치하기

프로젝트 폴더를 파일 탐색기로 열고 주소 표시줄에 `powershell`을 입력한다. 아래 명령은 한 줄이 끝난 뒤 다음 줄을 실행한다.

```powershell
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-jupyter.txt
.\.venv\Scripts\python.exe -m pip check
```

마지막 명령에서 `No broken requirements found.`가 나오면 기본 설치가 끝난 것이다. 기본 상태에서도 문자 n-gram TF-IDF 방식으로 모든 기능을 사용할 수 있다.

## 2. RTX GPU 임베딩 설치하기

GPU 방식은 선택 사항이다. 이 저장소에서는 Windows, Python 3.12, RTX 5080에서 CUDA 13.0용 PyTorch와 다국어 MiniLM을 확인했다.

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.12.0 --index-url https://download.pytorch.org/whl/cu130
.\.venv\Scripts\python.exe -m pip install -r requirements-embedding.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

`True`와 GPU 이름이 차례로 나오면 준비가 끝난 것이다. 웹 화면에서 `GPU 임베딩`을 처음 선택할 때 한국어 모델을 내려받으므로 인터넷 연결이 필요하고 시간이 조금 걸릴 수 있다. 모델을 불러오지 못하면 프로그램은 멈추지 않고 TF-IDF로 전환하며 화면에 사용한 방식을 알린다.

다른 CUDA 환경에서는 [PyTorch 설치 선택 페이지](https://pytorch.org/get-started/locally/)의 명령을 사용한다. 교실 PC에 GPU가 없으면 이 단계를 건너뛴다.

## 3. NVIDIA NIM 해설 준비하기

이 단계는 `NVIDIA NIM 데이터 해설` 탭을 사용할 때만 필요하다. 프로젝트 폴더 안이 아니라 한 단계 위 폴더에 키 파일을 만든다.

```powershell
notepad ..\nvidia_nim.txt
```

메모장 첫 줄에 발급받은 `nvapi-`로 시작하는 키만 넣고 저장한다. `nvidia_nim.txt`는 Git에 포함하지 않는다. 프로그램을 시작할 때는 키를 읽지 않고, 학생이 해설 질문을 보낼 때에만 읽는다. 질문, 최근 대화, 선택 학교의 통계·TF-IDF 표·역행렬 추천 결과가 NIM으로 전송된다. 이름이나 학번을 질문에 적지 않도록 안내한다.

키 파일을 다른 위치에 두려면 PowerShell에서 다음처럼 지정한 뒤 같은 창에서 서비스를 실행한다.

```powershell
$env:NVIDIA_NIM_KEY_FILE = "C:\안전한\위치\nvidia_nim.txt"
```

## 4. 서비스 열기

교사 PC에서 먼저 화면만 확인할 때는 로컬 모드로 연다.

```powershell
.\.venv\Scripts\python.exe mokpo_service.py
```

브라우저가 자동으로 열리지 않으면 PowerShell에 나온 `http://127.0.0.1:7860` 주소를 연다. 이 주소는 실행 중인 PC에서만 접속할 수 있다. 종료할 때는 PowerShell에서 `Ctrl+C`를 누른다.

학생 PC에서 접속할 날에는 공통 비밀번호 파일을 저장소의 한 단계 위에 두고 LAN 모드로 연다.

```powershell
notepad ..\mokpo_password.txt
.\.venv\Scripts\python.exe mokpo_service.py --lan
```

`ipconfig`에서 교사 PC의 IPv4 주소를 확인하고 학생에게 `http://IPv4주소:7860`을 알려 준다. 학생은 로그인 사용자 이름에 자기 이름을, 비밀번호에는 교사가 안내한 공통값을 넣는다. Gradio 외부 공유 링크는 만들지 않는다. Windows 방화벽 질문이 뜨면 현재 학교 네트워크가 사설 네트워크인지 확인한 뒤 Python의 사설 네트워크 통신만 허용한다.

화면 상단에 `31개교`, `674행`, `조회 20260601~20260729`, `실제 식단일 20260624~20260729`가 표시되는지 먼저 확인한다.

## 5. 학생 여섯 명이 사용하는 순서

### 프로필 평가와 행렬분해

1. 학생은 자기 PC에서 주소를 열고 자기 이름으로 로그인한다.
2. `내 프로필·30개 평가` 탭에서 `내 평가표 불러오기`를 누른다.
3. 공통 음식 15개와 학생별 순환 음식 15개에 1~5점을 준다. 시간이 부족하면 `평점 저장`으로 중간 저장한다.
4. 같은 이름으로 다시 로그인하면 질문 순서와 기존 평점이 복원된다.
5. 여섯 명이 30개씩 저장하면 `학생 행렬분해 실험` 탭에서 `현재 저장값으로 행렬분해`를 누른다. 학생용 LAN 화면에서는 이름이 `학생 1~6`으로 바뀐다.
6. 관측 행렬의 실제 180칸, 완성 행렬의 예측 90칸, 번호별 예상 Best·Worst를 비교한다.
7. 행렬분해 MAE와 전체평균 기준선 MAE를 비교한다. 실제 빈칸에는 정답이 없으므로, 정확도는 이미 아는 평점 일부를 가린 홀드아웃에서만 계산한다.
8. 수업 뒤 서버를 `Ctrl+C`로 끄고 로컬 모드로 다시 실행한다. 교사 PC의 `학생 행렬분해 실험` 탭에서 실제 이름별 현황을 확인하고 `전체 실제 평점 CSV`로 백업한다.

프로필 저장 파일과 수업 전 점검은 [학생 평점·행렬분해 실험 운영 안내](교사용_학생평점_행렬분해_실험.md)를 따른다.

### 학교 음식 탐색

1. `학교별 가치 음식` 탭을 열면 맨 위의 `학교 상관없는 전체 음식 중요도 랭킹`을 먼저 본다. 학교를 고르거나 버튼을 누르기 전부터 상위 50개가 표시된다.
2. 같은 음식이 한 행에만 나오는지 확인하고, 전체 등장 횟수와 등장 학교 수의 차이를 살펴본다.
3. 현재 수록본의 1위 배추김치는 전체 4,706개 음식 항목 중 349회, 31개교 중 27개교에서 나왔다. 화면에서 `349 ÷ 4706`과 `ln((1 + 31) ÷ (1 + 27)) + 1`을 확인한다.
4. 아래에서 분석할 학교를 고르고 `학교 핵심·가치 음식 계산`을 누른다.
5. `가장 자주 나온 핵심 메뉴`와 선택 학교의 `TF-IDF 데이터 가치 점수 상세` 1위가 전체 랭킹과 같은지 비교한다.
6. 점수가 높다는 말은 이 자료에서 중요한 패턴이라는 뜻이지, 맛이나 영양이 더 좋다는 뜻이 아님을 확인한다.

### 음식 30개 개인 추천

1. `30개 음식 역행렬 추천` 탭에서 학교를 고르고 `음식 30개 뽑기`를 누른다.
2. 30개 음식의 평점을 1~5 사이로 바꾼다. 음식 이름과 행 순서는 고치지 않는다.
3. `역행렬 추천 계산`을 누르고 미평가 음식 Best·Worst와 계산에 사용한 행렬 크기를 확인한다.
4. `음식 유사도 2차원 지도`에서 번호를 표와 맞춰 보고, 가까운 두 음식의 공통 글자 조각을 찾는다.
5. 지도는 이름의 유사도를 나타낼 뿐 영양이나 맛이 같다는 뜻은 아님을 기록한다.

### NIM으로 결과 해설하기

1. `NVIDIA NIM 데이터 해설` 탭에서 같은 학교를 고른다.
2. “데이터 가치 1위 음식은 왜 1위인가요?”처럼 표로 확인할 수 있는 질문을 적는다.
3. 답변의 숫자를 `학교별 가치 음식` 표와 대조한다.
4. 근거 표에 없는 내용을 물었을 때 모른다고 답하는지 확인한다.
5. NIM 답변도 틀릴 수 있으므로 발표 근거는 원래 표와 수식으로 제시한다.

### 식사 전

1. 학생마다 이름 대신 `학생A`부터 `학생F`까지 익명 코드를 정한다.
2. `학생 설문·개인 결과` 탭에서 좋아하는 메뉴, 피하고 싶은 메뉴, 선호 유형, 매운맛 선호를 입력한다.
3. `목포대 이틀 식사 전 예측 등록`을 누른다. 등록한 예측과 취향은 식사 후에 바꿀 수 없다.
4. 7월 30일과 31일의 콘텐츠 예측값과 근거를 활동지에 적는다.
5. 실제 만족도를 알기 전의 기록임을 확인한다. 예측값을 식사 뒤에 고치지 않는다.

### 7월 30일 식사 후

1. `목포대 2026-07-30 점심`을 선택한다.
2. 실제 만족도 1~5점과 가장 중요한 피드백 태그를 고른다.
3. `예측값과 실제 리뷰를 모둠에 추가`를 누른다.
4. 현재 익명 응답 표에 자기 코드와 날짜가 한 줄 생겼는지 확인한다.

### 7월 31일 식사 후

같은 취향 입력을 유지하고 7월 31일 식단의 리뷰를 추가한다. 한 학생이 한 날짜에 두 번 입력하면 중복으로 거절된다. 여섯 명이 이틀에 모두 응답하면 12행이 된다.

### 모둠 분석

학생이 각자 PC에서 실행했다면 먼저 각자 `익명 CSV 만들기`를 눌러 파일을 교사에게 보낸다. 교사 PC의 `모둠 피드백 분석` 탭에서 여섯 파일을 한꺼번에 선택하고 `CSV 합쳐서 분석`을 누른다. 한 PC를 함께 썼다면 바로 `현재 모둠 분석`을 누른다.

1. 합친 표가 학생 6명, 리뷰 12행인지 확인한다.
2. 콘텐츠 기반, 유저 기반, 혼합 추천의 MAE를 비교한다. MAE는 예측과 실제값의 차이를 절댓값으로 만든 뒤 평균 낸 값이라 작을수록 이 모둠의 리뷰를 더 가깝게 맞힌 것이다.
3. 상세 표에서 유저 기반 근거를 확인한다. 대상 학생의 해당 날짜 실제 평점은 가린 뒤 다른 학생의 리뷰로 예측한다.
4. 식성 군집과 밥친구 결과에서 비슷한 취향이 실제 평점도 비슷했는지 토의한다.
5. `익명 CSV 만들기`로 합친 결과를 다시 내려받아 보관한다. 여러 CSV에 같은 익명 코드와 날짜가 겹치면 중복으로 거절된다.

## 6. 세 추천 방식의 차이

### 콘텐츠 기반

학생이 적은 취향과 메뉴 문장을 벡터로 바꿔 코사인 유사도를 구한다. 선호 유형, 기피 키워드, 매운맛 차이도 점수에 반영한다. 다른 학생의 리뷰가 없어도 바로 계산할 수 있지만, 학생이 적지 않은 취향은 알 수 없다.

### 유저 기반

두 식단을 모두 평가한 뒤 사례별로 정답 한 개를 가린다. 대상 학생과 다른 학생이 공통으로 평가한 식단에서 평점 차이가 작을수록 이웃 가중치를 크게 준다. 공통 기록이 없으면 해당 식단의 모둠 평균, 모든 리뷰 평균, 기본값 순서로 전환한다. 표의 `유저 기반 근거` 열에 어떤 전환을 썼는지 남는다.

### 혼합

콘텐츠 점수와 유저 점수를 합친다. 공통 이웃이 있으면 두 점수를 같은 비중으로, 없으면 콘텐츠 점수를 더 크게 반영한다. 혼합 방식이 언제나 더 좋은 것은 아니므로 실제 MAE로 확인한다.

### 30개 평가 기반 의사역행렬 추천

이 기능은 다른 학생의 평점을 쓰는 유저 기반 추천과 다르다. 한 학생이 평가한 음식 30개와 각 음식 이름의 글자 N-그램 TF-IDF 벡터만 사용한다.

- `X`: 평가한 음식 30개의 특징표다. 한 행이 음식 하나이고, 한 열이 `돈까`, `까스` 같은 글자 조각 하나다.
- `y`: 학생이 매긴 1~5점이다. 보통인 3점을 빼서 좋아하는 방향은 양수, 싫어하는 방향은 음수로 만든다.
- `XXᵀ`: 평가 음식끼리 특징이 얼마나 겹치는지 나타내는 30×30 표다.
- `0.1I`: 비슷한 음식 때문에 계산이 지나치게 흔들리지 않도록 대각선에 더하는 작은 안전장치다.
- `pinv`: 보통 역행렬을 만들 수 없는 경우에도 가장 가까운 해를 구하는 무어–펜로즈 의사역행렬이다.

화면의 계산은 다음 순서다.

```text
G = X Xᵀ + 0.1I
w = Xᵀ pinv(G)(y - 3)
예상 평점 = 1~5로 제한(3 + 평가하지 않은 음식 벡터 × w)
```

`w`는 학생이 어떤 글자 특징을 좋아하거나 싫어하는지 나타내는 가중치다. 예를 들어 돈까스류를 높게 평가하면 공통 글자 조각이 있는 미평가 음식의 점수가 올라갈 수 있다. 이것은 음식 이름에서 얻은 관계이므로 재료·조리법·영양이 실제로 같다는 뜻은 아니다.

## 7. 다른 화면에서 볼 것

- `학교별 가치 음식`: 맨 위 전역 표는 `전체 TF = 전체 등장 횟수 ÷ 전체 음식 수`를 사용해 학교 선택 없이 음식당 한 줄로 순위를 세운다. 아래 학교별 표는 `TF = 선택 학교 안의 음식 비율`을 사용한다. 두 표 모두 `IDF = 여러 학교에서 드문 정도`, `데이터 가치 점수 = TF × IDF`이다.
- `30개 음식 역행렬 추천`: 직접 매긴 점수와 음식 이름의 TF-IDF 벡터를 이용해 아직 평가하지 않은 음식을 계산한다. 표의 `영향을 준 평가 음식` 열을 보고 결과를 설명한다.
- `음식 유사도 2차원 지도`: 추천에 쓴 고차원 벡터를 PCA로 두 축까지 줄인 그림이다. 축 자체에는 고정된 음식 의미가 없다.
- `NVIDIA NIM 데이터 해설`: 선택 학교의 계산 결과를 자연어로 읽어 주는 보조 기능이다. 새로운 급식 사실을 만드는 기능이 아니다.
- `Food MBTI`: 네 문항을 네 글자로 묶은 식성 별칭이다. 성격검사나 심리검사가 아니다.
- `AI 식단 실험실`: 여러 학생의 취향을 한 줄씩 넣어 Pareto 후보와 함께 나온 메뉴 쌍을 본다. 원가·잔반 실측 자료가 없으므로 모두 대체지표로 표시된다.
- `GPU 임베딩`: 뜻이 비슷한 한국어 표현을 비교하기 좋다. `TF-IDF`는 계산 근거가 눈에 보이고 같은 글자 조각에 민감하다. 두 결과가 다르면 어느 쪽이 실제 리뷰에 가까웠는지 토의한다.

## 8. 저장 범위와 해석 원칙

- 프로필 행렬분해 실험은 로그인 이름과 음식별 1~5점을 교사 PC의 SQLite에 저장한다.
- 학번, 반, 연락처, 질병명, 실제 알레르기 정보는 입력하지 않는다.
- 목포대 식사 전·후 리뷰 실험은 종전처럼 익명 코드와 학년 구간을 쓰고, 현재 서버 메모리에만 둔다. 내려받기를 눌렀을 때만 임시 폴더에 CSV가 생긴다.
- 수업 뒤 프로필 DB와 실제 평점 CSV는 교사가 관리하고, 공개 GitHub에는 넣지 않는다.
- 학생 여섯 명의 결과를 학교 전체 취향으로 일반화하지 않는다.
- 추천 점수는 건강 점수나 섭취 안전 판단이 아니다.
- 실제 알레르기와 영양 판단은 식당 표시와 영양사 안내를 따른다.
- 급식 취향만으로 진학할 학교를 정하지 않는다.
- NIM 질문에는 학생을 식별할 수 있는 내용을 적지 않고, 답변의 수치는 원래 계산 표와 대조한다.

## 9. NEIS 데이터 다시 받기

현재 공개 스냅샷으로 수업은 바로 진행할 수 있다. 기간을 늘려 다시 수집할 때만 교사용 인증키 파일을 사용한다.

```powershell
.\.venv\Scripts\python.exe scripts\collect_mokpo_meals.py --key-file "C:\안전한\위치\neis.txt" --start 20260601 --end 20260729 --school-output data\mokpo_schools.json --meal-output data\mokpo_meals_live.json
```

인증키는 저장소 폴더 밖에 두고 학생에게 배포하지 않는다. 수집 파일에는 공개 필드만 남고 인증키는 저장되지 않는다.
