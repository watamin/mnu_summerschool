# 목포 급식 취향 예측 운영 안내

이 서비스는 한 번의 점심을 두 번 기록하는 작은 실험이다. 학생은 음식 30개를 먼저 평가하고, 점심을 먹기 전에 예상 만족도를 확인한다. 식사 뒤에는 실제 만족도를 입력해 예상과 얼마나 달랐는지 본다. 두 번째 탭은 목포 지역 고등학교 급식 자료에서 주요 반찬을 읽는 보조 활동이다.

## 준비된 자료

| 자료 | 쓰임 |
| --- | --- |
| 목포시 중·고교 급식 스냅샷 | 전체 고등학교 주요 반찬 TF-IDF 분석 |
| 목포대학교 학생식당 7월 30·31일 점심 | 식사 전 예상과 식사 후 실제 만족도 비교 |
| 음식 45개 풀에서 배정한 30개 | 학생별 음식 평점 설문 |

목포대학교 메뉴는 NEIS 자료가 아니라 수업에서 비교할 검증 식단이다. 서비스는 메뉴 이름과 학생이 저장한 음식 평점만 사용한다.

## 1. 처음 한 번 설치하기

프로젝트 폴더에서 PowerShell을 열고 아래 명령을 차례로 실행한다.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-jupyter.txt
.\.venv\Scripts\python.exe -m pip check
```

마지막 줄에서 `No broken requirements found.`가 나오면 된다.

## 2. 서비스 열기

교사 PC에서 먼저 확인할 때는 다음 명령을 쓴다.

```powershell
.\.venv\Scripts\python.exe mokpo_service.py
```

브라우저가 열리지 않으면 `http://127.0.0.1:7860`으로 들어간다. 종료할 때는 PowerShell에서 `Ctrl+C`를 누른다.

학생들이 각자 PC에서 접속할 때는 LAN 모드로 연다.

```powershell
.\.venv\Scripts\python.exe mokpo_service.py --lan
```

`ipconfig`에서 교사 PC의 IPv4 주소를 확인한 뒤 `http://IPv4주소:7860`을 안내한다. 로그인이나 공통 비밀번호는 사용하지 않는다. Windows 방화벽 창이 나오면 학교 네트워크가 사설 네트워크인지 확인한 뒤 Python의 사설 네트워크 통신만 허용한다.

## 3. 학생이 하는 세 단계

### 1단계. 음식 30개 평가

1. 이름 칸에 수업에서 정한 별칭을 입력한다.
2. `내 평가표 불러오기`를 누른다.
3. 음식마다 1점부터 5점까지 평가하고 `30개 평점 저장`을 누른다.
4. 일부만 답해도 저장할 수 있지만, 점심 예측은 30개를 모두 평가한 뒤에만 실행된다.

같은 별칭으로 다시 불러오면 이전 평가를 이어서 수정할 수 있다. 서로 같은 별칭을 쓰면 같은 평가표를 보게 되므로 중복되지 않는 별칭을 정한다.

### 2단계. 오늘 점심 예상

1. 점심 날짜를 고른다.
2. `오늘 점심 예상하기`를 누른다.
3. 전체 예상 점수와 메뉴별 예상 점수, 비슷했던 평가 음식을 확인한다.

예상은 저장한 30개 음식 평점과 메뉴 이름의 문자 n-gram TF-IDF 유사도를 이용한다. 점심을 먹기 전의 값을 기록해 둔 뒤 3단계로 넘어간다.

### 3단계. 식사 뒤 비교

1. 실제 만족도를 1점부터 5점까지 입력한다.
2. `예측과 비교하기`를 누른다.
3. 예상 점수, 실제 점수, 실제-예상, 절대 오차를 함께 읽는다.

절대 오차가 작을수록 그날의 예상이 실제 만족도에 가까웠다는 뜻이다. 한두 번의 결과를 전체 취향의 정답으로 일반화하지 않는다.

## 4. 전체 고등학교 주요 반찬 탭

`고등학교 주요 반찬` 탭은 학생 입력 없이 바로 열린다. 목포 지역 고등학교 급식 전체를 합쳐, 밥·국·김치·면·후식류를 제외한 반찬을 TF-IDF 순서로 보여 준다. 따라서 매일 나오는 밥이나 김치보다 고등학교 급식에서 의미 있게 반복되는 주요 반찬을 먼저 살펴볼 수 있다.

```text
전체 TF = 해당 반찬의 전체 등장 횟수 ÷ 전체 반찬 수
IDF = ln((1 + 고등학교 수) ÷ (1 + 해당 반찬이 나온 고등학교 수)) + 1
TF-IDF = 전체 TF × IDF
```

점수가 높다는 것은 이 수집 자료에서 자주 나오면서 모든 고등학교에 흔하지 않다는 뜻이다. 맛·영양·인기의 순위나 학교 선택 기준은 아니다. 자동 제외 규칙은 분류를 단순하게 하기 위한 것이므로, 경계에 있는 메뉴는 표를 볼 때 함께 확인한다.

## 5. 저장과 개인정보

- 서비스는 입력한 별칭과 음식별 1~5점 평점을 교사 PC의 `runtime_data/student_profiles.sqlite3`에 저장한다.
- 이름 대신 수업용 별칭을 사용하고, 학번·반·연락처·질병명·실제 알레르기 정보는 입력하지 않는다.
- 외부 공개 링크로 잠시 시연할 때는 실제 이름이나 실제 학생 정보를 입력하지 않는다.
- 수업이 끝나면 DB는 교사가 보관하거나 학교의 보관 기준에 따라 삭제한다. GitHub에는 올리지 않는다.
- 추천 점수는 건강·영양·알레르기 안전을 판단하는 값이 아니다. 실제 식단과 알레르기 정보는 식당 표시와 영양사 안내를 따른다.

## 6. NEIS 급식 자료 갱신

현재 스냅샷으로 바로 수업할 수 있다. 기간을 늘려 다시 수집할 때만 인증키 파일을 저장소 밖에 두고 다음처럼 실행한다.

```powershell
.\.venv\Scripts\python.exe scripts\collect_mokpo_meals.py --key-file "C:\안전한\위치\neis.txt" --start 20260601 --end 20260729 --school-output data\mokpo_schools.json --meal-output data\mokpo_meals_live.json
```

인증키는 화면, 코드, 노트북, GitHub에 적지 않는다. 수집이 실패하면 확인된 기존 스냅샷으로 수업을 진행한다.
