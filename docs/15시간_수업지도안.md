# 15시간 수업지도안 — 우리 학교 급식 AI 개인추천기

## 운영 개요

- 대상: 코딩 기초를 조금 배운 중학교 2학년 6명
- 제작 시간: 3시간 × 5회 = 15시간
- 발표 시간: 3시간 × 1회
- 환경: 학생 1인당 PC 1대, Google Colab, 한국어 진행
- 팀 구성: 6명 전체가 하나의 서비스를 만들고 역할은 매회 순환
- 완성 시점: 5회차 종료 170분까지 기능 동결, 마지막 10분에 교사 승인

## 교사의 수업 원칙

1. 설명 20%, 학생 실행·수정·시험 80%를 목표로 한다.
2. 완성 코드를 먼저 모두 설명하지 않고 `예상 → 실행 → 결과 읽기 → 한 줄 수정` 순서를 반복한다.
3. 오류를 실패가 아니라 데이터·입력·코드 중 어디를 확인해야 하는지 찾는 활동으로 다룬다.
4. 학생은 매회 자신의 Colab 사본에 최소 한 번 직접 코드를 수정한다.
5. 생성형 AI가 만든 코드는 `무슨 입력을 받고 무엇을 출력하는가`를 학생이 설명할 때만 채택한다.
6. 이름·학번과 건강 관련 개인정보는 프로젝트 데이터에 넣지 않는다.

## 최신 AI 흐름 반영 지점

- 생성형 AI 활용 능력: 질문을 잘 쓰는 것뿐 아니라 답을 원본 데이터와 검증하는 활동
- 설명 가능한 AI: 추천 점수와 이유를 함께 표시하고 학생이 결과 변화를 설명
- 책임 있는 AI: 개인정보 최소화, 알레르기 주의, 편향과 데이터 부족 공개
- AI 엔지니어링: 프로토타입 제작, 시험 사례, 예비 데이터, 모델 카드, 발표 시연까지 한 흐름으로 경험
- AI 에이전트 맛보기: 5회차에 `모델 + 맥락 + 도구` 개념을 10분 소개하고, 현재 서비스가 NEIS라는 도구를 쓰지만 자율 에이전트는 아니라는 차이를 설명

## 4회차 180분 — 개인화 추천기와 서비스 화면

### 목표

- 개인정보를 쓰지 않는 취향 프로필을 설계한다.
- 추천 점수의 가감 요소와 알레르기 제외 규칙을 시험한다.
- Gradio 입력·버튼·출력 화면을 연결한다.

공개 점수식은 `0~100으로 제한(20 + 70×텍스트유사도 + 8×좋아함 일치 수 + 5×선호유형 일치 수 - 18×기피 일치 수 - 3×매운맛 차이)`이다. 20점 기준점은 감점 효과가 0점 하한에서 사라지지 않도록 둔다.

### 분 단위 운영

| 시간 | 활동 | 학생 행동 | 교사 확인 |
|---:|---|---|---|
| 0~15분 | 사용자 이야기 | “면을 좋아하고 오이를 피하는 학생” 시나리오 작성 | 이름·학번 없이 요구 표현 |
| 15~45분 | 취향 프로필 설계 | 좋아함·피함·유형·매운맛 입력값 수정 | 최대 5개 제한과 범위 확인 |
| 45~80분 | 점수 분해 | 1위 점수의 유사도·보너스·감점 표시 | 합계가 0~100 범위인지 확인 |
| 80~90분 | 휴식 |  |  |
| 90~125분 | 알레르기 제외 규칙 시험 | 가상 번호를 선택해 해당 메뉴 제외 확인 | 실제 정보 입력 금지, “안전 보장” 표현을 쓰지 않음 |

### 4회차 산출물

- 실행 가능한 개인추천기 화면
- 네 가지 시험 사례표
- 고정 안전 문구가 포함된 결과 화면

### 통과 기준

서비스 버튼이 세 번 연속 실행되고, 선택한 가상 알레르기 번호가 있는 메뉴가 추천표에 나타나지 않는다. 실제 학생의 의료 정보는 입력하지 않는다.

## 수업 중 생성형 AI 사용 규칙

1. 질문에 `중2가 이해할 한국어`, `입력과 출력`, `코드 한 줄씩 설명`을 포함한다.
2. 생성된 코드는 새 셀에서 먼저 실행한다.
3. NEIS 필드명과 추천 결과는 원본 JSON·테스트 결과와 비교한다.
4. 설명할 수 없는 코드는 팀 공유본에 합치지 않는다.
5. 학생 개인정보, API 키, 학교 내부 문서를 프롬프트에 넣지 않는다.
