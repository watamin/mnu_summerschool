# Jupyter 교재 활용 안내

이 교재는 급식 데이터를 읽는 일에서 시작해 데이터를 숫자로 표현하고, 간단한
모델을 학습·평가한 뒤 추천 결과를 설명하는 데까지 이어집니다. 정해진 시간표에
맞추기보다 앞 장의 결과를 이해했는지 확인한 뒤 다음 장으로 넘어가는 방식이
알맞습니다.

## 시작 전에 확인할 것

- `00_설치_준비.md`의 명령으로 프로젝트 전용 가상환경을 만듭니다.
- `.\.venv\Scripts\python.exe -m pip check`가 오류 없이 끝나는지 확인합니다.
- `.\.venv\Scripts\python.exe -m notebook`으로 Jupyter가 열리는지 확인합니다.
- 각 노트북의 표·그래프·계산 결과가 미리 저장되어 있는지 살펴봅니다.
- 실습 사본과 원본을 나누고, 백업할 때 `.venv` 폴더는 제외합니다.
- NEIS 인증키는 노트북이나 배포 파일에 넣지 않습니다.

## 권장 학습 흐름

| 흐름 | 사용할 장 | 이해해야 할 연결 |
|---|---|---|
| 실행 환경과 자료 구조 | 00, 부록 A | 값 → 목록 → 사전 → JSON → 파일 |
| 실제 데이터 가져오기 | 01 | URL과 조건 → GET 요청 → 상태 코드 → 응답 JSON |
| 분석 가능한 표 만들기 | 02 | 원본 문자열 → 메뉴·번호 분리 → 숫자 열 → 그래프 |
| 머신러닝의 기본 구조 | 부록 B | 데이터 → 특성 X·정답 y → 숫자 표현 → 학습 → 예측 → 오차 |
| 글자를 숫자로 표현하기 | 03 | n-gram → TF·DF·IDF → TF-IDF 벡터 |
| 비슷함 찾기 | 04 | 벡터 → 코사인 유사도 → 식단 군집 |
| 추천 규칙 적용하기 | 05, 06 | 취향 입력 → 점수 계산 → 순위와 이유 → 입력 화면 |
| 결과 검증하고 설명하기 | 07, 08 | 시험 사례 → 모델 카드 → 근거와 한계 설명 |

각 흐름은 하나의 질문으로 시작합니다. 먼저 저장된 결과를 읽고 코드가 무엇을
계산했는지 말로 설명합니다. 그다음 새 커널에서 전체 셀을 실행해 같은 결과가
나오는지 확인하고, `탐구 활동`의 값 하나만 바꾸어 결과 차이를 기록합니다.

## 머신러닝 기초를 확인하는 순서

부록 B는 뒤 장의 벡터와 추천 계산을 이해하기 위한 기준점입니다. 다음 질문을
순서대로 확인하면 공식만 외우는 일을 피할 수 있습니다.

1. 한 행에서 입력인 특성 `X`와 맞히려는 정답 `y`는 무엇인가?
2. 음식 이름을 그대로 계산하지 않고 원-핫 벡터로 바꾸는 까닭은 무엇인가?
3. 여덟 개의 평가에서 음식별 평균 네 개가 어떻게 학습되는가?
4. 김치 벡터와 학습된 값의 내적이 왜 예상 평점 5.0이 되는가?
5. 따로 둔 실제 평점 4.0과 비교한 절대오차가 왜 1.0인가?
6. 새 메뉴와 음식 사이의 의미상 가까움을 원-핫만으로 표현하기 어려운 까닭은 무엇인가?

이 연결이 보이면 03장의 TF-IDF를 단순한 새 공식이 아니라, 범주만 구분하던
원-핫보다 더 많은 정보를 담는 숫자 표현으로 이해할 수 있습니다.

## 저장된 결과와 직접 실행을 함께 쓰는 법

모든 노트북에는 정상 실행 결과가 저장되어 있습니다. 설치 중이거나 실행 전인
경우에도 표와 그래프를 먼저 읽을 수 있습니다. 직접 확인할 때는 Jupyter 메뉴에서
`Kernel → Restart Kernel and Run All Cells`을 선택합니다. 일부 셀만 순서 없이
실행하면 앞에서 만든 변수나 데이터가 없어질 수 있습니다.

다음 장으로 넘어가기 전에는 세 가지를 확인합니다.

- 코드 셀 왼쪽에 실행 번호가 차례대로 붙어 있다.
- 마지막 `chapter_result` 셀이 오류 없이 실행된다.
- 탐구 활동에서 바꾼 값과 달라진 결과를 한 문장으로 연결할 수 있다.

## NEIS와 예비 데이터

실제 요청은 학교 코드와 날짜, 최종 URL을 먼저 확인한 뒤 실행합니다. 네트워크나
NEIS 서버에 문제가 생기면 오류와 상태 코드를 기록하고 저장소의 예비 데이터로
같은 JSON·전처리·추천 과정을 이어 갑니다. 실시간 자료와 예비 자료를 섞어 부르지
않고, 화면에 표시된 출처를 그대로 기록합니다.

## 결과를 해석할 때 지킬 기준

- 추천 점수는 입력한 취향과 메뉴 표현을 비교한 값이며 건강 점수가 아닙니다.
- 군집 번호는 비슷한 수치의 식단을 묶은 이름일 뿐 등급이나 정답이 아닙니다.
- 한 번의 절대오차만으로 모델 전체의 성능을 단정하지 않습니다.
- 작은 표본에서 얻은 순위는 탐색 결과로 읽고 모집단 전체로 일반화하지 않습니다.
- 알레르기 번호는 계산 규칙을 확인하는 가상 값만 사용합니다.
- 실제 메뉴와 알레르기 정보는 학교 급식표와 영양사 안내를 다시 확인합니다.
- 이름, 학번, 반, 연락처, 질병명 같은 식별·건강 정보는 노트북에 입력하지 않습니다.

## 문제가 생겼을 때

| 문제 | 먼저 확인할 곳 | 이어 가는 방법 |
|---|---|---|
| 프로젝트 폴더를 찾지 못함 | PowerShell의 현재 위치 | 프로젝트 최상위 폴더에서 Jupyter 다시 실행 |
| 앞 셀의 변수가 없음 | 셀 왼쪽 실행 번호 | 커널을 다시 시작하고 전체 실행 |
| NEIS 요청 오류 | URL·학교 코드·날짜·상태 코드 | 오류를 기록하고 예비 데이터 사용 |
| JSON 경로 오류 | 현재 값의 `type()`과 `keys()` | 부록 A의 마지막으로 이해한 단계에서 다시 시작 |
| 그래프가 보이지 않음 | 같은 장의 위쪽 코드 셀 | 전체 실행한 뒤 표와 그래프를 대조 |
| 입력 위젯이 보이지 않음 | `pip show ipywidgets` 결과 | 패키지를 확인하고 커널 다시 시작 |
| 추천 결과가 비어 있음 | 가상 제외 번호와 후보 수 | 제외된 행을 확인하고 입력값 하나 변경 |
| 코드가 많이 달라짐 | 원본 노트북의 같은 셀 | 필요한 셀만 실습 사본에 복사 |

마지막에는 모델 카드의 데이터 출처, 계산 방법, 확인한 오차, 아직 해결하지 못한
한계를 화면 결과와 함께 설명합니다. 결과가 예상과 다를 때는 숨기지 않고 입력,
데이터, 표현 방법, 학습 규칙 가운데 어느 부분에서 차이가 생겼는지 찾습니다.
